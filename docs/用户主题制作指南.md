## 1. 主题到底是什么

**一个主题 = 一个 `.css` 文件。**

这个文件描述「文章正文」长什么样：标题多大、引用什么底色、表格边框什么颜色、图片怎么排版……你不需要写任何别的代码，也不需要改配置。

主题只作用于**文章内容区**（应用界面、编辑器的按钮、状态栏等外观由应用自己管理，不在你的主题范围内）。

---

## 2. 主题系统是怎么工作的（30 秒看懂）

整条链路是这样的：

```text
你在主题文件夹里写 my-theme.css
        │
        ▼
应用扫描 themes 目录里的 *.css        （每次重新扫描都会重新读文件）
        │
        ▼
自动处理你的 CSS：
  · 旧前缀 #nice / #wechat-article 统一改成 #article
  · 裸选择器（如 h1）自动加前缀变成 #article h1
  · @media / @supports 里面的规则也一起处理
        │
        ▼
合并进预览样式：
  [你的主题] + [横滑图组布局] + [脚注布局] + [代码高亮主题]
        │
        ▼
注入预览区 → 你立刻看到效果
  （同一份样式还用于：主题缩略图、复制到微信、导出 HTML/PDF/长图）
```

要点记三个：

1. **你只管写正文样式**，作用域（`#article` 前缀）应用帮你加；
2. **一份 CSS 到处用**：预览什么样，复制到微信、导出就是什么样；
3. **改了文件后要重新扫描**才会看到变化（见第 12 节）。

## 3. 动手前的准备：找到主题文件夹

### 3.1 打开主题文件夹

1. 打开 VellumStyle；
2. 点工具栏上的 **「主题」** 按钮（调色板图标）；
3. 在弹出的主题选择器底部，点 **「打开主题文件夹」**。

这一步会做两件事：在系统文件管理器里打开主题文件夹，**并顺便重新扫描一次主题列表**（后面改文件后也靠它刷新）。

### 3.2 主题文件夹在哪里

默认位置（Windows）：

```text
%APPDATA%\com.vellumstyle.desktop\themes
```

也就是：

```text
C:\Users\你的用户名\AppData\Roaming\com.vellumstyle.desktop\themes
```

macOS / Linux 用户直接用应用里的「打开主题文件夹」按钮，它会给你的正确路径。

### 3.3 文件名 = 主题 ID = 显示名

在主题文件夹里新建一个 CSS 文件，**文件名去掉 `.css` 就是主题的 ID 和显示名**：

```text
我的主题.css      → 主题名「我的主题」
everforest.css    → 主题名「everforest」
```

命名规则（违反会导致主题不出现或导入失败）：

- 只能用：字母、数字、中文、`-`、`_`、`.`；
- 不能以 `.` 开头（如 `.hidden.css` 不行）；
- 不能包含连续两个点（`a..b.css` 不行）；
- 不能用 Windows 保留文件名：`CON`、`PRN`、`AUX`、`NUL`、`COM1`~`COM9`、`LPT1`~`LPT9`；
- 文件不能是空文件。

**建议**：用简短、无空格的英文或中文名，例如 `morning-mist.css`、`晨雾.css`。

## 4. 你的第一个主题（逐行拆解）

### 4.1 创建文件

在主题文件夹里新建一个文件，命名为：

```text
我的第一个主题.css
```

### 4.2 粘贴这份完整代码

```css
/* 根容器：整篇正文的默认字号、颜色、行距、字体 */
#article {
  font-size: 16px;
  color: #333;
  line-height: 1.8;
  font-family: "Microsoft YaHei", "PingFang SC", sans-serif;
}

/* 段落 */
#article p {
  margin: 14px 0;
}

/* 一级标题 */
#article h1 {
  font-size: 28px;
  color: #1a1a1a;
  border-bottom: 2px solid #ddd;
  padding-bottom: 10px;
}

/* 二级标题 */
#article h2 {
  font-size: 22px;
  color: #2c3e50;
}

/* 引用块 */
#article blockquote {
  margin: 16px 0;
  padding: 10px 16px;
  background: #f7f8fa;
  border-left: 4px solid #3498db;
  color: #555;
}

/* 行内代码 */
#article p code {
  background: #f0f0f0;
  border-radius: 4px;
  padding: 2px 5px;
  font-family: Consolas, Menlo, monospace;
  font-size: 0.9em;
}

/* 表格 */
#article table {
  border-collapse: collapse;
  margin: 16px 0;
}
#article table th,
#article table td {
  border: 1px solid #d9d9d9;
  padding: 8px 12px;
}
#article table th {
  background: #f2f3f5;
}

/* 图片：最大不超过正文宽度，高度自动等比 */
#article img {
  max-width: 100%;
  height: auto;
}

/* 图注（独立成段的图片会变成 figure + figcaption） */
#article figure figcaption {
  text-align: center;
  color: #888;
  font-size: 14px;
  margin-top: 6px;
}
```

### 4.3 让应用看到它

1. 回到 VellumStyle，点 **「主题」**；
2. 点底部 **「打开主题文件夹」**（这步会重新扫描）；
3. 在列表里找到 **「我的第一个主题」**，点 **使用**。

随便写一篇带标题、引用、代码、表格、图片的 Markdown，右侧预览应该已经变成你定义的样子了。

### 4.4 每一段是什么意思

这里每段都在说同一句话：「**在文章区里，给某某元素设置什么样式**」：

| 选择器 | 管的是 |
| --- | --- |
| `#article` | 整篇正文的默认样式 |
| `#article p` | 段落 |
| `#article h1` / `h2` … | 各级标题 |
| `#article blockquote` | 引用块 |
| `#article p code` | 行内代码 |
| `#article table th/td` | 表格单元格 |
| `#article img` | 图片 |
| `#article figure figcaption` | 图片图注 |

你其实**可以不写 `#article` 前缀**，应用会自动补（下一节讲）。上面的写法是最保险、最明确的写法。

## 5. 作用域机制详解（必读）

应用会在加载主题时自动改写你的选择器，规则如下。

### 5.1 裸选择器自动加前缀

你写：

```css
h1 { color: red; }
```

应用改写成：

```css
#article h1 { color: red; }
```

所以哪怕你忘了加 `#article`，样式也只会作用于文章区，不会把应用界面的标题也染红。

### 5.2 已经写了前缀的保持不变

```css
#article h1 { color: red; }   /* 原样保留 */
```

### 5.3 旧版前缀自动归一化

从旧版 VellumStyle / mdnice 迁移来的主题里常见的 `#nice`、`#wechat-article` 会被自动改成 `#article`：

```css
#nice p { color: #333; }            →  #article p { color: #333; }
#wechat-article h2 { ... }          →  #article h2 { ... }
```

注意：`#nice-card` 这种**以 nice 开头的其他 ID** 不会被误伤。

### 5.4 逗号分隔的选择器逐个处理

```css
h1, h2 { color: red; }
```

会被分别改写：

```css
#article h1, #article h2 { color: red; }
```

### 5.5 支持的语法

| 语法 | 支持情况 |
| --- | --- |
| 普通规则 `选择器 { 声明 }` | ✅ |
| 伪元素 `::before` / `::after` | ✅ |
| 伪类 `:hover` / `:first-child` / `:nth-child(2n)` 等 | ✅ |
| `@media`（窗口宽度适配） | ✅ 内部规则同样自动作用域 |
| `@supports` | ✅ 同上 |
| `@font-face` / `@keyframes` | ✅ 整块原样透传 |
| 注释 `/* ... */` | 会被剥离（不影响功能） |
| `!important` | ✅ 保留，且复制到微信时也会保留 |

### 5.6 不支持的写法（写了会翻车）

**① `@import` 和 `@charset`：不支持，且会导致后续样式全部丢失。**

```css
/* 千万别这么写：后面的所有规则都会消失 */
@import url("other.css");
```

需要合并样式就手动把内容复制进同一个文件。

**② CSS 嵌套语法：不支持。**

```css
/* 不支持：嵌套写法会让解析错乱 */
h1 {
  .content { color: red; }
}
```

请写扁平规则：

```css
#article h1 .content { color: red; }
```

**③ `:root`、`body`、`html` 选择器：不要用。**

它们会被错误地改写成 `#article :root`、`#article body` 这种无效选择器。想给整篇文章设默认样式，直接写 `#article`。

**④ 花括号必须配对。**

解析器靠 `{` / `}` 找规则边界，括号不配对会吞掉后面的规则。写完保存前，建议在编辑器里确认括号是配对的（VS Code / 记事本都会提示）。

**⑤ 相对路径的 url()。**

`url(./font.woff)` 里的相对路径是相对**应用页面**解析的，不是相对你的主题文件夹，所以本地字体文件通常加载不出来。要加载字体/背景图，请用：

- 可访问的在线 URL，或
- `data:` 数据 URI（base64 内嵌）。

## 6. 全部元素速查表（枚举每一个元素）

> 这一节是**完整清单**。下面每一个 HTML 片段都来自应用真实渲染输出，你写的 Markdown 会变成什么结构，全在这里。
>
> 约定：代码块里第一行是 **Markdown 写法**，`→` 之后是**渲染出的 HTML 结构**（已省略 `data-line` 等系统属性，第 6.13 节单独说明）。
>
> 每个小节开头有用途标记：
> - 🎨 **可样式化**：主题的正常目标，模板里都有对应规则（见 `docs/主题模板.css` 与第 7 节）；
> - 📄 **仅原始 HTML**：只有手写/导入的 HTML 才会出现，模板提供兜底规则；
> - ⚠️ **系统托管**：应用或代码主题管理，别覆盖；
> - ℹ️ **说明**：结构提示，无需写样式。

### 6.1 根容器

> 🎨 可样式化

所有正文都包在 `#article` 里，主题样式全部从这里生效：

```html
<div id="article">
  ... 全部正文 ...
</div>
```

```css
#article { font-size: 16px; color: #333; line-height: 1.8; }
```

### 6.2 标题（文字在 .content 里）

> 🎨 可样式化

```markdown
## 二级标题
```

```html
<h2><span class="prefix"></span><span class="content">二级标题</span><span class="suffix"></span></h2>
```

`h1` ~ `h6` 结构完全相同。要点：

- **标题文字在 `.content` span 里**：字号、颜色、字重写 `#article h2 .content`；
- `#article h2` 管标题整体的间距、边框、背景；
- `.prefix` / `.suffix` 是装饰插槽（默认空内容、默认隐藏），可以做"01."编号、图标等；
- 标题整体带 `data-line` 属性（同步滚动用，主题不用管）。

```css
#article h2 { margin: 24px 0 12px; border-bottom: 1px solid #eee; padding-bottom: 6px; }
#article h2 .content { font-size: 22px; color: #2c3e50; font-weight: 700; }
#article h2 .prefix { display: inline-block; margin-right: 8px; color: #999; }
```

### 6.3 段落与行内文字（完整清单）

> 🎨 可样式化（其中 `<a>` / `<u>` 属 📄 仅原始 HTML）

```markdown
正文：**加粗** *斜体* ~~删除线~~ ==高亮== `行内代码`
```

```html
<p>
  正文：<strong>加粗</strong> <em>斜体</em>
  <s>删除线</s> <mark>高亮</mark> <code>行内代码</code>
</p>
```

对应选择器（**注意删除线是 `<s>`，不是 `<del>`**）：

```css
#article p { margin: 14px 0; }
#article strong { font-weight: 600; }
#article em { font-style: italic; }
#article s { color: #999; text-decoration: line-through; }
#article mark { background: #fff3bf; color: inherit; padding: 0 2px; }
#article code { font-family: Consolas, Menlo, monospace; }
#article p code,
#article li code { background: #f0f0f0; padding: 2px 5px; border-radius: 4px; font-size: 0.88em; }
```

另外两个行内元素可能以**原始 HTML** 形式出现（应用放行、不会转成脚注）：

```html
<a href="https://example.com">原始链接</a>
<u>下划线</u>
```

```css
#article a { color: #3498db; text-decoration: underline; }
#article u { text-decoration: underline; }
```

`{文字|拼音}` 会渲染成注音（ruby），见 6.12。

### 6.4 列表（内容包在 section 里）

> 🎨 可样式化

```markdown
- 无序项
1. 有序项
```

```html
<ul><li><section>无序项</section></li></ul>
<ol><li><section>有序项</section></li></ol>
```

嵌套列表时，子列表在 `section` 内部：

```html
<ul><li><section>父项
  <ul><li><section>子项</section></li></ul>
</section></li></ul>
```

```css
#article ul { padding-left: 28px; list-style: disc; }
#article ol { padding-left: 28px; list-style: decimal; }
#article li section { margin: 4px 0; }
#article li::marker { color: #3b82a0; }
```

### 6.5 引用块（嵌套层级用结构选择器）

> 🎨 可样式化

```markdown
> 一级引用
> > 二级引用
```

```html
<blockquote class="multiquote-1">
  <p>一级引用</p>
  <blockquote class="multiquote-1">
    <p>二级引用</p>
  </blockquote>
</blockquote>
```

**重要（实测结论）**：当前渲染管线里，无论嵌套多少层，每个引用块都带 `class="multiquote-1"`，**没有 `multiquote-2` / `multiquote-3`**。想按层级区分样式，用结构选择器（后代选择器）：

```css
#article blockquote { border-left: 4px solid #3498db; background: #f7f8fa; }
#article blockquote blockquote { border-left-color: #e67e22; background: #fdf6f0; }
#article blockquote blockquote blockquote { border-left-color: #9b59b6; background: #faf6fc; }
```

### 6.6 代码块（内部配色归「代码主题」管）

> 🎨 容器可样式化 · ⚠️ 内部 `.hljs-*` 系统托管

~~~~markdown
```ts
const x = 1;
```
~~~~

```html
<pre class="custom"><code class="hljs">
  <span class="hljs-keyword">const</span> x = <span class="hljs-number">1</span>;<br>
</code></pre>
```

- 行内的 `span.hljs-keyword` / `hljs-number` / `hljs-string` 等是**代码主题**（主题选择器第二个标签页）负责的配色；
- 代码换行是 `<br>`；
- 文章主题可以装饰**容器**：圆角、边框、阴影、外边距：

```css
#article pre.custom { border-radius: 8px; border: 1px solid #eee; box-shadow: 0 2px 8px rgba(0,0,0,.06); }
```

### 6.7 流程图 Mermaid

> 🎨 可样式化（svg 为运行时生成，只做容器样式）

~~~~markdown
```mermaid
graph TD
  A --> B
```
~~~~

渲染分两步：

1. **静态 HTML** 只是一段原始文本：

   ```html
   <pre class="mermaid">graph TD
     A --> B</pre>
   ```

2. 应用在运行时把它替换成 `<svg>`（`#article pre.mermaid svg`）。

出错时会有错误态：`pre.mermaid.mermaid-error`。

```css
#article pre.mermaid { text-align: center; margin: 18px 0; }
#article pre.mermaid svg { max-width: 100%; height: auto; }
#article pre.mermaid.mermaid-error { color: #9f1239; text-align: left; }
```

### 6.8 表格（外层有容器，内部有 thead/tbody）

> 🎨 可样式化

```markdown
| 列1 | 列2 |
| --- | --- |
| a | b |
```

```html
<section class="table-container">
  <table>
    <thead><tr><th>列1</th><th>列2</th></tr></thead>
    <tbody><tr><td>a</td><td>b</td></tr></tbody>
  </table>
</section>
```

```css
#article .table-container { overflow-x: auto; margin: 18px 0; }
#article table { border-collapse: collapse; width: 100%; }
#article table th,
#article table td {
  border: 1px solid #d9d9d9;
  padding: 8px 12px;
  vertical-align: middle;
}
#article table th { background: #f2f3f5; font-weight: 600; }
#article table tr:nth-child(2n) td { background: #fafcfe; }
#article table td img { display: inline-block; vertical-align: middle; }
```

> 单元格内容统一 `vertical-align: middle`，并单独处理单元格内图片，避免行内图片按 baseline 对齐导致和同行文字错位。

### 6.9 图片、图注、表情、横滑图组

> 🎨 figure/figcaption/行内图可样式化 · ⚠️ 经典表情与横滑布局系统托管

**① 独立成段的图片**（单独一行）：包成 `figure`，图片的 alt/描述变成图注文字，`img` 的 alt 清空：

```markdown
![图片描述](https://example.com/a.png)
```

```html
<figure>
  <img src="https://example.com/a.png" alt="">
  <figcaption>图片描述</figcaption>
</figure>
```

带尺寸（`=200x120`）时，`img` 上会有 `width="200" height="120"` 属性；带标题（`"标题"`）时，`img` 上有 `title="标题"` 属性：

```html
<figure>
  <img src="..." alt="" width="200" height="120" title="图片标题">
  <figcaption>图片描述</figcaption>
</figure>
```

```css
/* 兜底：任何位置的图片都不超过容器宽度（含表格单元格内的图片） */
#article img { max-width: 100%; height: auto; }
#article figure { display: flex; flex-direction: column; align-items: center; margin: 22px 0; }
#article figure img { max-width: 100%; height: auto; border-radius: 8px; }
#article figure figcaption { margin-top: 8px; color: #888; font-size: 14px; text-align: center; }
```

> 通用 `#article img` 兜底很重要：表格单元格、行内等不包在 `figure` 里的图片，靠它保证不溢出容器。

**② 嵌在文字里的图片**（表情、行内图）：就是 `p img`，不包 figure：

```html
<p>文字里插入 <img src="..." alt="表情"> 的效果</p>
```

```css
#article p img { display: inline-block; vertical-align: middle; max-width: 100%; }
```

**③ 微信经典微表情**：应用插入的是带官方类名的行内 `img`，尺寸由内联样式固定（20×20）：

```html
<img src="..." class="rich_pages wxw-img" data-ratio="1" data-w="20"
     style="display:inline-block;width:20px !important;height:20px !important;vertical-align:middle;..." alt="表情">
```

主题不用管它，也不要试图覆盖它的尺寸。

**④ 横滑图组**（素材库多选轮播插入，或手写一行多图）：

```html
<section class="imageflow-layer1"><section class="imageflow-layer2">
  <section class="imageflow-layer3"><img class="imageflow-img" src="..." alt=""></section>
  <section class="imageflow-layer3"><img class="imageflow-img" src="..." alt=""></section>
</section></section>
<p class="imageflow-caption">&lt;&lt;&lt; 左右滑动见更多 &gt;&gt;&gt;</p>
```

布局由应用托管（带 `!important`），主题只能改文字类样式：

```css
#article .imageflow-caption { color: #999; font-size: 14px; text-align: center; }
```

### 6.10 链接与脚注

> 🎨 可样式化（`.footnote-item` 块级布局系统托管）

**普通 Markdown 链接** `[文字](url)` 会被渲染成**脚注引用**：

```html
<span class="footnote-word">⌈文字⌋</span><sup class="footnote-ref">[1]</sup>
```

**标准脚注标记** `正文[^注1]` 直接渲染引用：

```html
<p>正文<sup class="footnote-ref">[3]</sup></p>
```

文末脚注区：

```html
<h3 class="footnotes-sep"></h3>
<section class="footnotes">
  <span id="fn1" class="footnote-item" style="display:block;">
    <span class="footnote-num" style="display:inline;width:auto;">[1] </span>脚注内容
  </span>
</section>
```

（`.footnote-item` / `.footnote-num` 的块级布局由应用 `!important` 托管，主题改颜色、字号没问题。）

```css
#article .footnote-word { color: #3b82a0; }
#article .footnote-ref { color: #3b82a0; font-size: 12px; }
#article .footnotes { margin-top: 28px; padding-top: 14px; border-top: 1px solid #eee; color: #777; font-size: 14px; }
```

### 6.11 数学公式（运行时排版）

> 🎨 可样式化（容器级）

```markdown
行内公式 $E=mc^2$

$$ x^2 + y^2 = z^2 $$
```

静态 HTML 里 `$...$` / `$$...$$` 先以文本形式存在，应用运行时用 MathJax 替换成：

```html
<mjx-container jax="SVG">行内公式</mjx-container>
<mjx-container jax="SVG" display="true">块级公式</mjx-container>
```

```css
#article mjx-container { font-size: 18px; }
#article mjx-container[display="true"] { display: block; margin: 18px 0; text-align: center; }
```

## 7. 手把手带你写一个主题（从零开始，覆盖所有元素）

这一节我们**一步一步**从空文件写出一套覆盖第 6 节全部元素的主题。每一小步都是：给一段 Markdown → 给你对应的 CSS → 解释为什么。你可以跟着敲，也可以直接复制。

### 7.1 准备

1. 在主题文件夹新建 `手把手主题.css`；
2. 每完成一小步就保存，然后回应用里点 **「主题」→「打开主题文件夹」** 重新扫描；
3. 为了验证效果，准备一篇"测试文章"，把第 6 节每类元素各写一段（标题、加粗、列表、引用、代码、表格、图片、脚注、公式、目录……）。

> 不确认某个选择器是否生效时，用探针：给规则临时加 `outline: 2px solid red;`，预览里出现红框就是命中了。

### 7.2 第一步：全局基调（#article + p）

先定整篇的字体、字号、颜色、行距，以及段落的间距。这决定 90% 的观感。

```css
#article {
  font-family: "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif;
  font-size: 16px;
  line-height: 1.85;
  color: #3a3f45;
  background: #ffffff;
  padding: 0 4px;
}

#article p {
  margin: 14px 0;
  text-align: justify;
}
```

### 7.3 第二步：标题 h1 ~ h6

标题结构是 `<h2><span class="prefix"></span><span class="content">文字</span><span class="suffix"></span></h2>`。

我们给 h1/h2 加分隔线，给 h3~h6 只调字号颜色；再用 `.prefix` 给 h2 做"编号感"装饰。

```css
#article h1 .content,
#article h2 .content,
#article h3 .content,
#article h4 .content,
#article h5 .content,
#article h6 .content {
  display: block;
}

#article h1 .content { font-size: 28px; color: #1f2d3d; font-weight: 700; }
#article h1 { margin: 30px 0 14px; padding-bottom: 10px; border-bottom: 2px solid #dce6f0; }

#article h2 .content { font-size: 22px; color: #2b4a63; font-weight: 700; }
#article h2 { margin: 26px 0 12px; padding-bottom: 8px; border-bottom: 1px solid #e6eef6; }

#article h3 .content { font-size: 18px; color: #33475b; font-weight: 600; }
#article h3 { margin: 22px 0 10px; }

#article h4 .content,
#article h5 .content,
#article h6 .content { color: #40566b; font-weight: 600; }

/* h2 的装饰插槽：手动在标题前写「01.」之类的文字（.prefix 里没有内容就不显示） */
#article h2 .prefix {
  display: inline-block;
  margin-right: 8px;
  color: #9db8d2;
  font-size: 16px;
  font-weight: 400;
}
```

### 7.4 第三步：行内文字

加粗、斜体、删除线（**`<s>`**）、高亮（`==`）、行内代码、原始链接、下划线：

```css
#article strong { color: #1f2d3d; font-weight: 700; }
#article em { color: #5a6472; }
#article s { color: #a0a8b0; }
#article mark { background: #fff1b8; color: #594300; padding: 0 3px; border-radius: 3px; }

#article p code,
#article li code {
  background: #f2f4f7;
  color: #b5475d;
  padding: 2px 6px;
  border-radius: 4px;
  font-family: "SFMono-Regular", Consolas, Menlo, monospace;
  font-size: 0.88em;
}

#article a { color: #3b82a0; text-decoration: underline; }
#article u { text-decoration: underline; }
```

### 7.5 第四步：列表

```css
#article ul { padding-left: 30px; list-style: disc; }
#article ol { padding-left: 30px; list-style: decimal; }
#article li section { margin: 6px 0; }
#article li::marker { color: #3b82a0; }
```

### 7.6 第五步：引用块（含嵌套层级）

实测所有引用块都带 `multiquote-1`，所以**嵌套层级用结构选择器区分**：

```css
#article blockquote {
  margin: 18px 0;
  padding: 12px 18px;
  background: #f4f8fb;
  border-left: 4px solid #7fb0cf;
  color: #54626f;
}

/* 第二层（引用里的引用） */
#article blockquote blockquote {
  border-left-color: #8fc3a9;
  background: #f4faf6;
}

/* 第三层 */
#article blockquote blockquote blockquote {
  border-left-color: #c9a7d6;
  background: #faf7fc;
}
```

### 7.7 第六步：代码块与流程图

代码块内部配色归「代码主题」，我们只装饰容器；流程图居中并限制宽度：

```css
#article pre.custom {
  border-radius: 10px;
  border: 1px solid #e3e9f0;
  box-shadow: 0 2px 10px rgba(31, 45, 61, 0.05);
}

#article pre.mermaid {
  text-align: center;
  margin: 18px 0;
}
#article pre.mermaid svg {
  max-width: 100%;
  height: auto;
}
#article pre.mermaid.mermaid-error {
  color: #9f1239;
  text-align: left;
}
```

### 7.8 第七步：表格

表格包在 `.table-container` 里，结构有 `thead/tbody`：

```css
#article .table-container {
  overflow-x: auto;
  margin: 18px 0;
}
#article table {
  border-collapse: collapse;
  width: 100%;
  font-size: 15px;
}
#article table th,
#article table td {
  border: 1px solid #dfe6ee;
  padding: 9px 14px;
}
#article table th {
  background: #f2f6fa;
  color: #2b4a63;
  font-weight: 600;
}
#article table tr:nth-child(2n) td {
  background: #fafcfe;
}
```

### 7.9 第八步：图片、图注、表情、横滑

独立图片（`figure`）、图注（`figcaption`，文字来自 alt）、行内图片（表情）、横滑提示文字：

```css
#article figure {
  display: flex;
  flex-direction: column;
  align-items: center;
  margin: 22px 0;
}
#article figure img {
  max-width: 100%;
  height: auto;
  border-radius: 8px;
}
#article figure figcaption {
  margin-top: 8px;
  color: #8a94a0;
  font-size: 14px;
  text-align: center;
}

/* 行内小图（表情等）保持行内，别给 display:block */
#article p img {
  display: inline-block;
  vertical-align: middle;
  max-width: 100%;
}

/* 横滑图组提示文字（布局归应用托管） */
#article .imageflow-caption {
  color: #8a94a0;
  font-size: 14px;
  text-align: center;
}
```

### 7.10 第九步：链接与脚注

Markdown 链接会变成脚注引用（`.footnote-word` + `.footnote-ref`），文末是 `.footnotes` 区：

```css
#article .footnote-word { color: #3b82a0; }
#article .footnote-ref { color: #3b82a0; font-size: 12px; }
#article .footnotes {
  margin-top: 28px;
  padding-top: 14px;
  border-top: 1px solid #e6eef6;
  color: #7a8694;
  font-size: 14px;
```

### 7.11 第十步：数学公式、分隔线、定义列表、注音、目录

### 7.12 第十一步：响应式收尾

`@media` 按**应用窗口宽度**生效（不是预览面板宽度），把窗口拉窄才能看到效果：

### 7.13 完整主题模板（覆盖所有元素）

- [ ] 独立图片（有图注）、行内表情（不换行）、横滑图组（提示文字颜色）

## 8. 复杂的样式怎么写（进阶技巧）

模板能覆盖 90% 的场景。想做更精致的效果，靠下面这些技巧。每条都注明**能不能带到微信**（复制/导出时样式会被内联，微信阅读器最终决定渲染效果）。

### 8.1 用 CSS 变量统一配色（换肤只需改一处）

把主题色定义在 `#article` 上，规则里用 `var()` 引用。以后想换主色调，只改顶部几个变量：

```css
#article {
  --text: #3a3f45;
  --heading: #1f2d3d;
  --accent: #3b82a0;
  --border: #dfe6ee;
  --bg-soft: #f4f8fb;
  color: var(--text);
}
#article h2 .content { color: var(--heading); }
#article blockquote { border-left-color: var(--accent); background: var(--bg-soft); }
#article table th,
#article table td { border-color: var(--border); }
```

> 微信提示（实测）：**微信编辑器会剥离 `--x` 这类自定义属性的定义**（粘贴进编辑器后定义变成空声明），只保留 `var()` 引用——不写兜底的话颜色会全部失效。所以 CSS 变量必须写成带具体色值兜底的形式：
>
> ```css
> color: var(--ink, #38342c);
> ```
>
> 微信端变量定义被剥掉后，浏览器会使用第二个参数的具体色值，排版颜色恢复正常。想彻底稳妥也可以直接写死色值，不用变量——**「墨岚」「墨岚·星空」已全部改为写死色值**（见第 10 节背景修复），模板仍保留兜底写法供参考。

### 8.2 伪元素装饰（引用引号、角标、分隔装饰）

伪元素在复制到微信时会被内联（应用开了 `inlinePseudoElements`），可以放心用。经典例子：给引用块加一对引号：

```css
#article blockquote {
  position: relative;
  padding: 16px 20px 16px 44px;
}
#article blockquote::before {
  content: "“";
  position: absolute;
  left: 12px;
  top: 6px;
  font-size: 40px;
  color: rgba(59, 130, 160, 0.35);
  font-family: Georgia, serif;
  line-height: 1;
}
```

> 注意：`content` 里的内容如果是引号等特殊字符，用双引号包起来并转义，如 `content: "\201C"`。`position: absolute` 需要父元素 `position: relative`（上面已经写好）。移动端对绝对定位的支持正常，但别用它做覆盖全屏的布局。

标题的装饰插槽（`.prefix` / `.suffix`）也是做这类效果的好地方：在正文标题前写 `<span class="prefix">01.</span>`，然后用 CSS 控制样式：

```css
#article h2 .prefix {
  display: inline-block;
  margin-right: 10px;
  padding: 2px 8px;
  border-radius: 4px;
  background: var(--accent, #3b82a0);
  color: #fff;
  font-size: 14px;
}
```

### 8.3 渐变与阴影

渐变、阴影都是标准 CSS，微信阅读器支持良好。例子：

```css
/* 分隔线：中间实两边淡 */
#article hr {
  height: 1px;
  border: 0;
  background: linear-gradient(90deg, transparent, #a9c1d6, transparent);
}

/* 代码块：柔和投影 */
#article pre.custom {
  box-shadow: 0 4px 16px rgba(31, 45, 61, 0.08);
}

/* 标题：底部渐变强调线 */
#article h2 {
  border-bottom: 0;
  background: linear-gradient(90deg, #3b82a0 0%, #3b82a0 64px, #e6eef6 64px, #e6eef6 100%) left bottom / 100% 2px no-repeat;
  padding-bottom: 10px;
}
```

### 8.4 表格进阶

利用 `thead` / `tbody`、`:first-child` / `:last-child` 做更精细的表格：

```css
#article .table-container { overflow: hidden; border-radius: 10px; border: 1px solid #dfe6ee; }
#article table { border-collapse: collapse; width: 100%; }
#article thead th {
  background: linear-gradient(180deg, #f7fafc, #e9f1f7);
  color: #2b4a63;
  padding: 10px 14px;
}
#article tbody td { border-top: 1px solid #eef2f7; padding: 9px 14px; }
#article tbody tr:first-child td { border-top: 0; }
/* 首列突出 */
#article tbody td:first-child { font-weight: 600; color: #33475b; }
```

### 8.5 图片进阶

```css
#article figure img {
  border-radius: 12px;
  border: 1px solid #e8edf3;
  box-shadow: 0 4px 14px rgba(31, 45, 61, 0.08);
  transition: transform 0.2s ease;
}
/* 桌面预览悬停放大（移动端无 hover，仅预览好玩） */
#article figure img:hover { transform: scale(1.02); }
```

> 微信提示：`transition` / `:hover` 在手机上没有实际交互，但无害。正式文章不建议依赖悬停效果传达信息。

### 8.6 动画（@keyframes）

```css
@keyframes vs-fade-in {
  from { opacity: 0; }
  to { opacity: 1; }
}
#article blockquote {
  animation: vs-fade-in 0.6s ease;
}
```

> 微信提示（实测）：`animation` 声明虽会被内联，但 **`@keyframes` 关键帧定义在 juice 内联时会被丢弃**，所以微信里动画不会真正运行。动画只适合应用预览演示，正式文章别依赖它传达信息。

### 8.7 选择器优先级与 !important 的使用时机

**什么时候用 `!important`**：对抗应用托管层（第 9 节的横滑布局、脚注块级布局、代码块基础布局）时，只有 `!important` 能压过系统规则。复制到微信时 `!important` 会原样保留。

```css
/* 例：硬改代码块容器圆角（系统基础样式在主题之后，需 !important 才能压过） */
#article pre.custom { border-radius: 4px !important; }
```

**什么时候别用**：正常可样式区域（标题、引用、表格……）写 `!important` 会让以后想覆盖变得很痛苦，也不利于别人基于你的主题二次修改。能用普通声明解决的就别加。

优先级速记（从高到低）：`!important` > 行内样式 > `id`（`#article`）> class / 属性 > 标签。主题里所有选择器都以 `#article` 开头，所以天然比裸标签选择器高。

### 8.8 调试复杂样式的套路

1. **探针**：临时加 `outline: 2px solid red !important;`，看红框出现在哪，确认选择器命中；
2. **分步叠加**：一次只加一个效果，验证没问题再加下一个，避免多效果互相干扰；
3. **隔离**：复杂效果先在「放开展示」宽度下调好，再切「手机端」宽度检查窄屏表现；
4. **怀疑系统层**：不生效先查第 9 节托管区，再决定是否 `!important`；
5. **怀疑解析器**：括号没配对、用了 `@import` / CSS 嵌套，都会让后续规则静默丢失——保存前检查括号。

### 8.9 微信里的样式边界：能带过去什么，带不过去什么（实测）

复制到微信时，应用用 juice 把全部主题样式**内联进每个元素的 `style` 属性**（微信只认内联样式）。下面这张表是实测结果，也是你"大刀阔斧改造"的边界：

| 样式 | 能不能进微信 | 说明 |
| --- | --- | --- |
| 颜色 / 背景（含渐变）/ 边框 / 圆角 / 阴影 / 边距 / 字号 / 行距 / 宽高 | ✅ | 全部内联，微信渲染正常 |
| 结构伪类 `:first-child` / `:nth-child(2n)` | ✅ | 内联时按当前 DOM 求值，斑马纹等直接生效 |
| 伪元素 `::before` / `::after` | ✅ | 内联成**真实的 `<span>`**（`content` 文字也会成为微信正文的一部分） |
| 动态伪类 `:hover` / `:active` / `:focus` | ❌ | 无法内联，微信里没有悬停态 |
| `@media` 媒体查询 | ❌ | 无法内联；响应式规则只在应用预览里有效 |
| `@keyframes` 动画 | ❌ | `animation` 声明会残留，但关键帧定义被丢弃，不会真的动 |
| `@font-face` 自定义字体 | ❌ | 字体加载不了；`font-family` 会回落成系统字体 |
| CSS 变量 `--x` / `var(--x)` | ⚠️（定义会被剥） | 微信编辑器会剥离 `--x` 定义，`var()` 引用失效；必须写 `var(--x, 具体色值)` 兜底（实测兜底写法在子元素上保留并生效），或直接写死色值。**注意：不要在文章根元素上定义 `--x`**——实测根元素 style 一出现 `--x` 定义，整段 style 就被清空 |
| 文章根元素 `#article` 上的 `background` 等全部样式 | ✅（有条件） | 内置「全栈蓝」的根元素 style（**纯长手属性 + 写死值，无任何 CSS 变量**）在微信端**完整保留，全页背景正常显示**；而「墨岚」v2 的根 style 因带 `--x` 定义 / `var()` 被整段清空（style 只剩空分号）。区别在写法不在根元素本身：**根元素不写 CSS 变量、写成长手属性，全页背景就能带进微信**；块级元素（标题/段落/引用/表格/代码等）的背景无论怎么写都正常保留 |
| 未显式写 `text-align` 的列表内容 | ⚠️ | 微信编辑器会给列表项内容（`<li><section>`）默认套**两端对齐**，中英混排/超长串时中文会被拉开很难看。内置「全栈蓝」的 `#article li section` 显式写了 `text-align: left` 所以正常。自定义主题请在**根元素和 `li section` 上显式写 `text-align: left`**；段落想两端对齐就只在 `#article p` 上写 `text-align: justify` |
| `flex` | ⚠️ | 现代微信端正常；老版本有兼容问题，别做复杂嵌套 flex |
| `position: absolute` | ❌（实测） | 粘贴进微信时会被**剥掉**，依赖它的装饰（伪元素生成的角落引号、骑线徽章等）会失去定位而错位。主题里别用 `absolute` + `left/top` 做装饰定位，改用块级 + `text-align: center` 等流内方案 |
| `transform` / `transition` | ⚠️（会被剥） | `transform` 粘贴进微信时被剥掉：旋转/位移/缩放类装饰在微信端失效（如拍立得图片会恢复正位，属可接受降级）；`transition` 无 hover 交互，实际用不上 |

**结论——大刀阔斧的边界：**

- **放心改**：全套配色、系统字体栈、字号行距、标题装饰、引用/表格/列表/脚注的边框背景、图片圆角阴影、渐变分隔线、斑马纹、伪元素装饰；
- **有条件改**：flex、CSS 变量（子元素写 `var(--x, 兜底)` 可用，根元素别定义 `--x`）——能用，但保持简单；
- **别用**：`position: absolute` / `transform`——粘贴进微信会被剥掉，装饰会错位或失效；
- **改了也白改**：`@media` 响应式、`:hover`、`@keyframes` 动画、`@font-face` 字体——只在应用预览里有效，进不了微信。

**自适配原则**：微信端没有媒体查询，窄屏适配要靠"百分比宽度 + `max-width: 100%` + 可换行"这类天生自适应的属性完成，而不是 `@media`。另外给 `#article` 加 `overflow-wrap: break-word; word-break: break-word;` 可防止超长英文串/URL 溢出容器（模板与「墨岚」均已内置）。

**验证原则**：以「复制到微信 → 草稿箱 / 手机预览」为最终标准。应用预览能显示但微信里失效的样式，就是上表 ❌ 的那几类。

## 9. 应用托管区域：这些不用你管，也别乱改

下面几个区域由应用统一注入样式（排在你的主题**之后**，部分还带 `!important`）。你的主题里写了同名规则也可能不生效，不是写错了：

### 9.1 代码块配色

代码块内部（背景、关键字颜色等）由**代码主题**管理——主题选择器里的第二个标签页「代码主题」，有 260+ 种可选。

文章主题里可以给 `#article pre.custom` 加圆角、边框、阴影这些容器装饰；但**不要**覆盖 `.hljs` 的 `background` / `color` 规则，那会和代码主题打架。

### 9.2 横滑图组的布局

`imageflow-layer1/2/3` 的 flex 布局、scroll-snap 都带 `!important`，主题改了不会生效。可以改的只有文字类样式，比如 `.imageflow-caption` 的颜色。

### 9.3 脚注的块级布局

`.footnote-item` 的 `display` / 边距等带 `!important`；颜色、字号可以改。

### 9.4 微信经典微表情

经典表情以行内 `<img>` 插入，尺寸（20×20）由内联样式 `!important` 固定，主题别试图改大小。

### 9.5 数学公式与 Mermaid 的运行时结构

公式和流程图是应用运行时排版出来的（MathJax / mermaid.js），主题只做容器和文字样式（`mjx-container`、`pre.mermaid`），不要假设它们的内部结构。

### 9.6 微信富媒体卡片

`mpvoice`、`mp-common-mpaudio`、`mp-common-videosnap`、`mp-common-clmusic` 是官方卡片结构，靠大量 `data-*` 属性和内联样式工作，主题不要覆盖它们的结构样式，否则发布后卡片可能失效。

### 9.7 通用建议

- 不要写全局 `#article img { display: block }`——会把行内表情挤成独立一行。行内图用 `#article p img`，独立图用 `#article figure img`；
- 不要覆盖 `.hljs`；
- 想改代码块整体底色，优先去「代码主题」里选一个底色合适的，而不是在文章主题里硬改。

## 10. 背景色与白底兜底

**应用预览里，文章背景能改**：文章根元素是 `<section id="article">`，主题里写 `#article { background: ... }` 会被内联到这个元素上，应用预览正常显示。

**微信端能不能带过去，取决于根元素 style 的写法**：内置「全栈蓝」的根元素 style 是**纯长手属性 + 写死值（无 CSS 变量）**，粘贴进微信后完整保留，全页背景纹理照常显示；而「墨岚」v2 的根 style 里写了 `--x` 定义和 `var()` 引用，粘贴后被整段清空（style 只剩一串空分号），背景随之丢失。**所以全页背景可以进微信**，条件是：根元素上不写任何 `--x` 定义、不用 `var()`，`background` 按下面的例子写长手属性 + 写死色值。（仓库里的「墨岚.css」「墨岚-星空.css」都已按这个配方修复，「墨岚」整页纸底背景**已实测在微信端存活**，根因确认就是 CSS 变量。）

好消息是：**块级元素**（标题、段落、引用、表格、代码块等）的内联样式在微信端完整保留，不受上述限制。想让微信端也有"设计感底色"，除了把整页背景写安全外，也可以把背景做到块级元素上（引用卡、表格底色、标题色带等）。

三种做法：

```css
/* ① 整块纯色背景 */
#article { background-color: #fdf6ec; }

/* ② 渐变/纹理背景（底色透明，靠底下白底透出） */
#article {
  background-color: rgba(0, 0, 0, 0);
  background-image: linear-gradient(90deg, rgba(50, 0, 0, 0.03) 0%, rgba(255, 255, 255, 0) 11.49%);
  background-size: 20px 20px;
  background-repeat: repeat;
}

/* ③ 多层渐变叠加（"全栈蓝"主题就是这么做纸感纹理的） */
#article {
  background-color: rgba(0, 0, 0, 0);
  background-image:
    linear-gradient(90deg, rgba(50, 0, 0, 0.03) 0%, rgba(255, 255, 255, 0) 11.49%),
    linear-gradient(360deg, rgba(50, 0, 0, 0.04) 0%, rgba(255, 255, 255, 0) 12.16%);
  background-size: 20px 20px, 20px 20px;
  background-repeat: repeat, repeat;
}
```

> ⚠️ 根元素 `#article` 上**别用 CSS 变量**（`--x` 定义 / `var()` 引用），也别用 `background:` 简写——都展开成 `background-color` / `background-image` / `background-size` / `background-repeat` 等长手属性、写死色值（「全栈蓝」就是这么写的，实测能存活）。

「全栈蓝」主题（mdnice-17）用的就是 ③：`background-color` 透明 + 两层细斜纹渐变，透明度只有 3%~4%，叠在白色上形成淡淡的纸张纹理。

**改不了的两处**：

- **预览区"舞台"背景**（文章外面的那片灰/白区域）：那是应用界面，主题管不到；
- **微信文章页的页面底色**：只要根元素 style 写法安全（无 CSS 变量、长手属性），全页背景可以带进微信（内置「全栈蓝」已实测存活）；若根元素写了 `--x` / `var()`，微信会清空整段 style，背景丢失。

**白底兜底的判定细节**：应用只把 `background` / `background-color` 的**不透明值**视为"设了背景"。纯 `background-image`（像全栈蓝那样）会被判定为"没设底色"，预览时自动垫白——这正好和微信白底一致，纹理照样显示，所以不用担心。

所以：

- 想要文章白底：不用写任何背景（应用帮你兜底）；
- 想要**有颜色的背景**：显式写 `#article { background: #fdf6ec; }`；
- 想要透明/纹理背景：写 `transparent` 或 `rgba(0,0,0,0)` + `background-image`，预览照样垫白、纹理显示在白底上。

想稳妥就整块不透明色；想要纹理/透明效果，记住应用预览透出的是**纸底**、微信端是**白底**，按"白底 + 纹理"来设计即可。微信端要背景感：根元素写法安全（无 CSS 变量、长手属性）时可以整页背景；拿不准就做在块级元素上（引用卡、表格底色、标题色带），块级样式不受限制。

## 11. 预览、缩略图、复制、导出：所见即所得

一份主题 CSS 在四个地方使用，效果一致：

| 位置 | 说明 |
| --- | --- |
| 预览区 | 实时渲染，改完重扫+切换就能看 |
| 主题选择器缩略图 | 用固定示例文章渲染的小卡片 |
| 复制到微信 | 全部样式被 juice 内联进 HTML（微信只认行内样式） |
| 导出 HTML / PDF / 长图 | 同样基于内联后的成品 |

因此**预览里长什么样，发出去就是什么样**（严格说：凡是能被内联的样式都一致，见 8.9 的边界表）。几个相关事实：

- 复制/导出时 `!important` 会保留（`preserveImportant: true`）；
- 伪元素（`::before` / `::after`）也会内联（`inlinePseudoElements: true`）；
- 应用自带的「暗色模式」只影响应用界面（菜单、面板），**不会**影响文章区——文章配色始终由你的主题决定，避免污染公众号成品。想要深浅两套，就做两个主题文件（如 `晨雾.css` / `晨雾-暗色.css`），手动切换。

## 12. 调试与快速迭代

推荐的工作流：

```text
改 CSS → 保存 → 点「主题」→ 点「打开主题文件夹」（= 重新扫描）→ 点「使用」看效果
```

不用重启应用：每次重新扫描都会**重新读取文件内容**，保存即生效。

几个实用的调试技巧：

1. **探针大法**：不确定某个选择器有没有命中，临时给它加一条醒目的样式：

   ```css
   #article blockquote { outline: 2px solid red; }
   ```

   预览里出现红框 = 选择器命中；没出现 = 选择器没写对（对照第 6 节速查表）。

2. **`@media` 依据的是应用窗口宽度，不是预览面板宽度**：预览区虽然支持「放开展示 / 微信桌面端 / 手机端」三种宽度，但 `@media (max-width: 480px)` 这类规则按**整个应用窗口**的宽度判断。所以把窗口拉窄才能看到手机端断点效果，单纯切预览模式不会触发。需要按容器宽度适配的话，把 `#article` 前缀写全再考虑 `@container`（注意容器查询内部的裸选择器不会被自动作用域）。

3. **样式不生效先查优先级**：
   - 是不是命中了「应用托管区域」（第 9 节）？
   - 是不是被代码主题盖住了（`.hljs`）？
   - 是不是 CSS 语法有误（括号不配对 / 用了 CSS 嵌套 / `@import`）导致后面的规则丢失？

4. **主题文件里的注释会被剥离**，别依赖注释传递信息。

## 13. 常见问题排查表

### Q1：主题文件放进去了，列表里没有

按顺序检查：

1. 文件名是否符合命名规则（第 3.3 节）？以 `.` 开头、含 `..`、Windows 保留名都会失败；
2. 文件是不是空文件？（空文件会被跳过）
3. 是不是在**桌面版**里？浏览器版（Web 模式）没有主题目录，只有内置主题；
4. 有没有重新扫描？（点一次「打开主题文件夹」）

### Q2：改了文件，效果没变

确认保存了、并且重新扫描了。如果还不行，检查文件里是否用了 `@import` 或括号不配对——这两种情况会让后续规则静默丢失。

### Q3：为什么标题的字号/颜色不生效

标题文字在 `.content` span 里。字号、颜色要写 `#article h1 .content`；`#article h1` 管的是标题整体的间距、边框。对照第 6.2 节。

### Q4：为什么删除线选择器写 del 不生效

删除线 `~~文字~~` 渲染成 `<s>` 而不是 `<del>`。用 `#article s`。（`<del>` 只在原始 HTML 里出现。）

### Q5：为什么嵌套引用写 multiquote-2 不生效

当前渲染管线里所有引用块都只有 `multiquote-1`。按层级区分要用结构选择器：`#article blockquote blockquote`、`#article blockquote blockquote blockquote`。对照第 6.5 节。

### Q6：为什么代码块背景不跟我的主题走

代码块配色由「代码主题」决定（主题选择器第二个标签页）。文章主题里对 `pre.custom` 设置的 background 会被代码主题的 `.hljs` 背景盖住。这是设计行为，不是 bug。

### Q7：图片的宽高、图注怎么控制

独立图片在 `figure` 里：`#article figure`（整体布局）、`#article figure img`（图片）、`#article figure figcaption`（图注文字）。图注文字来自图片的 alt/描述。

### Q8：想基于某个内置主题修改

内置主题的 CSS 文件在项目仓库：

```text
src/themes/builtin/*.css
```

选一个最接近的（比如 `default.css` 或某个 mdnice 主题），把内容复制成你自己的 `.css` 文件再改。注意文件里可能已经是 `#article` 前缀或 `#nice` 前缀，两者都能正常识别。

### Q9：我的主题和内置主题重名

用户主题会**覆盖**同 id 的内置主题。比如你建了 `default.css`，就会覆盖默认主题。想保留内置的，换个文件名。

### Q10：中文文件名可以吗

可以。`晨雾.css`、`我的主题.css` 都行，显示名就是文件名。

### Q11：暗色模式下我的主题会不会自动变暗

不会。应用暗色模式只作用于应用界面，文章区始终用你主题的配色。需要暗色就做单独的暗色主题文件。

## 14. 分享与导入

### 导出 / 分享

把 `.css` 文件直接发给对方即可。对方有两种方式使用：

1. **导入**：点「主题」→ 底部「导入主题文件」→ 选择你的 `.css`，应用会复制到主题文件夹并刷新；
2. **手动**：把文件放进自己的主题文件夹，重新扫描。

### 同名覆盖

对方导入的文件名如果和已有主题相同，会覆盖旧主题。

### 删除用户主题

主题选择器里，**用户主题**卡片上有一个垃圾桶按钮（收藏星标旁边）：

1. 点一下垃圾桶 → 按钮变成红色「确认删除」；
2. 再点一次「确认删除」→ 文件从主题文件夹删除，列表自动刷新；3 秒内不确认会自动复原。

几点说明：

- **内置主题没有删除按钮**（它们随应用打包，删不掉）；
- 删除的是 `themes/` 目录里对应的 `.css` 文件，想找回需要重新导入或放回文件；
- 如果删的是正在使用的主题，应用会自动回退到可用主题（文档记住的主题 ID 不会被污染）；
- 如果用户主题与内置主题同名（覆盖了内置），删除后**同名内置主题自动恢复**。

### 导入失败提示

导入时文件名会经过安全校验，违反命名规则（第 3.3 节）会提示"主题 id 为空或仅含非法字符"等错误，改个合法文件名再试。
