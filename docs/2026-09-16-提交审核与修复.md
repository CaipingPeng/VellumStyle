## 重构质量与后续优化

- 三组 Rust 模块拆分前后的声明名称已对照，未发现原有函数、结构体或常量丢失。Windows 下的 Rust 测试也已验证命令宏重导出可以编译。`no_proxy()` 与共用客户端的调整合理。
- 目前子模块普遍 `use super::*`，父模块又重导出所有子模块。文件变短了，但依赖关系仍较隐蔽。建议后续独立收紧非命令模块的可见性、使用明确导入；命令模块保留包含 Tauri 生成宏的必要重导出，避免与功能修复混在一起。
- 字号转换仍是轻量 CSS 扫描器，不是完整 CSS 解析器。复杂 `:is()` / `:where()` 参数中的逗号、复杂选择器关系、`calc()` 等写法尚不具备完整语义支持。后续扩展自定义主题能力时，应优先统一主题作用域与字号转换的解析方式，并加入真实浏览器下的嵌套角色测试。
- 图片缓存每次写入都扫描目录，而且协议响应等待写入与淘汰结束。大量图片时，可进一步合并淘汰任务、增加失败临时文件的过期清理，再通过实际命中率和加载耗时判断收益。
- release 的 LTO、strip、单 codegen unit 配置没有发现明显冲突。此次没有打各平台发布包，不能据此量化体积、启动耗时或确认 macOS universal 构建时长。
