# 视频号卡片（mp-common-videosnap）官方草稿结构与踩坑记录

> 结论来自 2026-08 实测：用户在公众号草稿箱里用官方入口插入视频号卡片后，
> 从编辑器中复制出的真实 DOM。

## 官方草稿结构

```html
<section class="channels_iframe_wrp custom_select_card_wrp wxw_wechannel_card_not_horizontal" nodeleaf="">
  <mp-common-videosnap class="js_uneditable custom_select_card channels_iframe videosnap_video_iframe"
    data-pluginname="mpvideosnap" data-url="..." data-headimgurl="..." data-username="..."
    data-nickname="..." data-desc="..." data-nonceid="..." data-authiconurl="..."
    data-width="720" data-height="960" data-type="video" data-id="..." draggable="true">
  <br class="ProseMirror-trailingBreak">
</section>
```

要点：

- section 类名：`channels_iframe_wrp custom_select_card_wrp`，竖版追加
  `wxw_wechannel_card_not_horizontal`，并带 `nodeleaf=""`。
- **不能带内联 style 或 data-tool**。微信粘贴解析识别不到官方卡片节点时，
  会在内部再包一层官方 section，造成双层结构、选中态淡绿描边与卡片错位。
- `data-height` 存的是**卡片显示比例**（竖版 3:4、横版 16:9），不是视频原生比例
  （例如 9:16 的视频存 720×960 而不是 720×1280）。
- widget class 不带 `mp_common_widget`；`draggable="true"` 官方有，保留。
- `nodeleaf` 与 `draggable` 必须进 sanitize 白名单，否则会被 DOMPurify 剥掉，
  section 少了 nodeleaf 标记，微信同样不认。

## 踩坑记录（按时间顺序）

1. **带内联 style + data-tool 的 section**：微信不识别，内部再包一层官方 section，
   选中态描边对不上卡片（右边短一截）。教训：官方容器不能加未知属性。
2. **裸 mp-common-videosnap**：markdown 渲染器会把它包进 `<p>`（带
   `text-align:left`），卡片左对齐、居中失效。教训：必须输出块级 section，
   不能依赖微信自动包裹。
3. **臆测类名组合**：先后试过 `custom_select_card_wrp`-only、
   `channels_iframe_wrp`-only 等，微信都重新包一层。教训：不要猜，让用户从草稿箱
   复制官方卡片真实 DOM。
4. **data-height 用原生比例**：9:16 视频存 720×1280，草稿箱按 3:4 裁剪封面，
   与预览（按 9:16）视野不一致。教训：草稿态用显示比例。
5. **旧内容不生效**：修好生成器后，用户旧文档里的旧结构依然带 style/data-tool。
   教训：导出要做历史内容归一化，把旧结构统一清洗成官方结构。
